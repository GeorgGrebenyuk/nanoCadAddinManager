# nanoCAD Add-in Manager -- Краткое руководство

Настоящий проект представляет собой форк приложения для AutoCAD "Add-in Manager", созданного [ChuongHo](https://github.com/chuongmep). Отличия от оригинального кода приведены в корневом ReadMe в блоке описания "Authors and changing from ChuongHo's original version (CadAddinManager)". Ниже будет приведена информация об особенностях разработки на .NET API с использованием данного приложения.

# Примечания к версиям

Так как nanoCAD .NET API испытывает значительно меньшее число изменений по сравнению с AutoCAD .NET API, то для отладки приложений можно использовать только 2 активные версии:

- для nanoCAD 21, nanoCAD 22 --  версию для 22;

- для nanoCAD 23, 24, 25 -- версию для 23;

В nanoCAD 26 появится поддержка Avalonia, поэтому если Ваш проект её использует, то Вам будет необходимо проекты с nanoCAD 26 реализовывать на соответствующей версии nanoCAD Add-in Manager.

# Состав библиотек CAD Add-in Manager

Вся программная логика описывается библиотекой классов `nanoCadAddinManager.dll` (в оригинальной версии она называлась `CadAddinManager.dll`); при ней располагается набор вспомогательных библиотек `Mono.Cecil`, `Mono.Cecil.Mdb`, `Mono.Cecil.Pdb`, `Mono.Cecil.Rocks` используемых для чтения содержимого .NET библиотек по аналогии с System.Reflection, только с большей функциональностью.

# Принцип работы CAD Add-in Manager

Принцип работы модуля заключается в копировании загружаемых .NET-сборок ~~вместе с зависимыми файлами~~  БЕЗ зависимых файлов из заданного каталога во временную папку с подменой имен командных методов. 

## Предполагаемая схема работы:

1. Запускается экземпляр целевого приложения -- чистая или с надстройками платформа nanoCAD;
2. С помощью команды `AddInManagerManual` загружается пользовательская библиотека;
3. Из-под того же окна `AddInManagerManual` тестируются все доступные командные методы. При желании изменить код, пользователь его меняет в VS 2022 или иной используемой IDE, пересобирает;

Если студия ругается, что не может скопировать сборку, т.к. она занята, то из-под окна `AddInManagerManual`удаляем кнопкой **Remove** загруженную сборку и повторяем попытку пересборки решения.

Если студия его пересобрала без удаления через **Remove**, то в окне `AddInManagerManual` через контекстное меню делаем Reload для ранней сборки.

**Внимание**! Если у Вас имеется более одной загружаемой библиотеки, то в диалоге загрузки библиотек вам необходимо выбрать их все. В противном случае при попытке вызвать код функции, использующей команду из другой DLL у вас выплюнется "MissingMethodException" и всё свалится в фатал. С новым подходом в фатал всё не свалится, но вы потеряете возможность перегружать засимые сборки -- изменения из других библиотек не будут подтягиваться без перезагрузки nanoCAD. Иногда это не требуется, зависимостей я пока не понял.

## Основные отличия от привычной схемы разработки:

1. Целевая САПР уже запущена;

2. Отлаживаемые библиотеки грузятся в неё через интерфейс CadAddinManager и выгружаются также через него;

3. Точки останова работать **не будут**! 

Для вывода отладочных сообщений используйте встроенный в CadAddinManager стек вызовов -- команды `System.Diagnostics.Trace.WriteLine()` или `System.Diagnostics.Debug.WriteLine()`.

Если с `Debug.WriteLine()` будет выводиться только простой ч\б текст, то с `Trace.WriteLine()` может выводить цветной текст, если использовать соответствующий префикс в аргументе сообщения:

```cs
Trace.WriteLine($"Warning: This will be a red color");
Trace.WriteLine($"Error: This will bea red color");
Trace.WriteLine($"Add: This will bea blue color");
Trace.WriteLine($"Modify: This will bea cyan color");
Trace.WriteLine($"Delete: This will bea gray color");
```

# Возможные проблемы

Если загруженную сборку не получается загрузить (выбрасывается исключение File not loaded), то закройте nanoCAD и

* удалите все данные из папки `%LOCALAPPDATA%\Temp\AcadAddins`;

* удалите все данные из папки `%APPDATA%\Cad Addin Manager`;

Перезапустите nanoCAD
