# nanoCAD Add-in Manager -- Краткое руководство

Настоящий проект представляет собой форк приложения для AutoCAD "Add-in Manager", созданного [ChuongHo](https://github.com/chuongmep). Отличия от оригинального кода приведены в корневом ReadMe в блоке описания "Authors and changing from ChuongHo's original version (CadAddinManager)". Ниже будет приведена информация об особенностях разработки на .NET API с использованием данного приложения.

# Примечания к версиям

Так как nanoCAD .NET API испытывает значительно меньшее число изменений по сравнению с AutoCAD .NET API, то для отладки приложений можно использовать только 2 активные версии:

- для nanoCAD 21, nanoCAD 22 --  версию для 22;

- для nanoCAD 23, 24, 25 -- версию для 23;

В nanoCAD 26 появится поддержка Avalonia, поэтому если Ваш проект её использует, то Вам будет необходимо проекты с nanoCAD 26 реализовывать на соответствующей версии nanoCAD Add-in Manager.

# Состав библиотек CAD Add-in Manager

Вся программная логика описывается библиотекой классов `nanoCadAddinManager.dll` (в оригинальной версии она называлась `CadAddinManager.dll`); при ней располагается набор вспомогательных библиотек `Mono.Cecil`, `Mono.Cecil.Mdb`, `Mono.Cecil.Pdb`, `Mono.Cecil.Rocks` используемых для чтения содержимого .NET библиотек по аналогии с System.Reflection, только с большей функциональностью.

# Принцип работы CAD Add-in Manager

Принцип работы модуля заключается в копировании загружаемых .NET-сборок ~~вместе с зависимыми файлами~~  БЕЗ зависимых файлов из заданного каталога во временную папку с подменой имен командных методов. 

## Предполагаемая схема работы:

1. Запускается экземпляр целевого приложения -- чистая или с надстройками платформа nanoCAD;

2. С помощью команды `AddInManagerManual` загружается пользовательская библиотека;

<mark> Библиотека обязательно должна быть standalone! То есть, не требующей иных зависимостей, иначе зависимости не будут скопированы!</mark>

**Примечание**: Вне зависимости, используются ли "живые" dll'ки из состава nanoCAD .NET API или их referene-версии из состава NuGet-пакетов, эти библиотеки должны копироваться в выходной каталог, т.к. иначе Mono.Cecil выкинет ошибку о невозможности идентификации типов;

## Основные отличия от привычной схемы разработки:

1. Целевая САПР уже запущена;

2. Отлаживаемые библиотеки грузятся в неё через интерфейс CadAddinManager. и выгружаются также через него;

3. Точки останова работать **не будут**! Для вывода отладочных сообщений используйте встроенный в CadAddinManager стек вызовов -- команду `System.Diagnostics.Debug.WriteLine("...text")`, её результат будет представлен в окне `AddinManagerDockPanel` и вкладке `Listener` у `AddInManagerManual`;
